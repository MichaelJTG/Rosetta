# Sprint 0 · Scaffold inicial

## Objetivo

Levantar la estructura base del proyecto ROSETTA con todas las piezas necesarias para empezar a programar en MVP-1.

## Hecho

- Estructura de carpetas: `src/rosetta/{core,adapters,llm,api,cli}`, `tests/`, `docs/{adr}`, `corpus/`, `examples/`, `vault/`.
- `pyproject.toml` con uv, dependencias core y dev, configuración de ruff y mypy strict.
- `.gitignore`, `.env.example`, `LICENSE` provisional.
- Modelos Pydantic completos: `HallazgoMaestro`, `DatosRedTeam`, `DatosBlueTeam`, `DatosCompliance`, enums `Severidad`, `FuenteRedTeam`, `MarcoNormativo`.
- Esqueletos con `NotImplementedError` de: `TraductorSimbiotico`, `NormativaRAG`, `GrafoCorrelacion`, `ClaudeClient`, adaptadores `NucleiAdapter`, `AmassAdapter`, `WazuhAdapter`, `CorpusLoader`.
- API FastAPI y CLI Typer con endpoints de placeholder.
- Tests básicos de modelos (`test_models.py`) con fixture canónica de AWS key filtrada.
- `CLAUDE.md` con contexto del proyecto y reglas para Claude Code.
- Documentación: `README.md`, `docs/ARCHITECTURE.md`, `docs/ROADMAP.md`, `docs/adr/001-orquestacion-sobre-fork.md`.
- Ejemplo canónico: `examples/finding_aws_leaked_key.json`.
- Vault Obsidian con estructura de 9 carpetas, plantillas y notas índice. Insight de Carlos registrado en `06_Procedimientos/insight-carlos-procedure-drift.md`.

## Aprendizajes

- La decisión de no forkear open source (ADR-001) simplifica mucho el diseño: solo adaptadores thin.
- El Hallazgo Maestro como contrato central permite testear cada capa por separado con mocks.
- El insight de Carlos sobre procedure drift encaja naturalmente en el roadmap como MVP-5 sin romper la arquitectura — el RAG ya admite metadato `tipo`.
